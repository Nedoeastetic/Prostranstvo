# Почта.Пространство

**Команда «Крендели»** — Трек «Цифровой двойник отделения Почты России»

Веб-сервис для проектирования, инвентаризации и оптимизации пространства отделений почтовой связи (ОПС): 2D-редактор планировки, автоматический учёт оборудования, проверка планировки на ошибки, ИИ-рекомендации по улучшению планировки и 3D-визуализация.

## Возможности

- **Импорт схем** (`ImportModal`) — загрузка существующих планов в форматах JSON, SVG или растровых изображений (PNG/JPG) как подложки для последующей обрисовки.
- **2D-редактор** (`Editor2D`, `Sidebar`, `canvasIcons`) — расстановка объектов (кассовые окна, терминалы, стеллажи, места ожидания, камеры и др.), привязка к стенам, функциональное зонирование помещения (входная группа, зона обслуживания, хранение, офис, техническая зона, коридор).
- **Инвентаризация** (`InventoryPanel`) — автоматический подсчёт оборудования и метрика эффективности использования площади (Space Utilization) в реальном времени, на основе фактической геометрии плана.
- **Проверка корректности** (`ValidationPanel`) — поиск коллизий объектов, объектов вне контура помещения, дублирующихся идентификаторов.
- **ИИ-ассистент** (`AIAssistant`) — карточки рекомендаций по улучшению планировки (проблема → обоснование → эффект для бизнеса → применение в один клик).
- **3D-визуализация** (`View3D`, на базе `three.js`) — автоматическая генерация 3D-сцены из данных плана с цветовым кодированием по типу зоны, без ручного моделирования.
- **Демо-данные** (`src/data/demoPlan.ts`) — готовый пример плана отделения для демонстрации без импорта.

## Стек технологий

| Слой | Технология |
|---|---|
| Frontend | React 18 + TypeScript |
| Сборка | Vite 6 |
| Стили | Tailwind CSS 4 |
| Состояние приложения | React Context + `useReducer` (`src/store.tsx`) |
| 2D-графика | HTML5 Canvas (собственная реализация в `Editor2D`/`canvasIcons`) |
| 3D-графика | three.js |
| Drag & Drop | `@dnd-kit/core`, `@dnd-kit/sortable` |
| Графики метрик | `recharts` |
| Анимации | `framer-motion` |
| Прочее | `uuid`, `date-fns`, `canvas-confetti`, `lucide-react` (иконки) |

> В зависимостях также присутствует `@supabase/supabase-js`, но в текущей демо-версии клиент Supabase не используется — все данные хранятся в памяти приложения (см. раздел [«Данные и хранение»](#данные-и-хранение)).

## Требования

- **Node.js** версии 18 или новее (рекомендуется 20 LTS)
- **npm** версии 9+ (устанавливается вместе с Node.js)

Проверить версии:

```bash
node -v
npm -v
```

## Установка и запуск

1. Распакуйте/склонируйте проект и перейдите в его директорию:

   ```bash
   cd <папка-проекта>
   ```

2. Установите зависимости:

   ```bash
   npm install
   ```

3. Запустите сервер разработки:

   ```bash
   npm run dev
   ```

4. Откройте в браузере адрес, который выведет Vite (по умолчанию `http://localhost:3000`, конфигурация — `vite.config.js`).

5. На экране входа поля e-mail и пароль уже предзаполнены (`admin@pochta.ru` / `admin123`) — это демо-заглушка авторизации, реальная проверка учётных данных не выполняется. Нажмите «Войти», чтобы попасть на главную страницу и в редактор.

### Сборка production-версии

```bash
npm run build
```

Собранные файлы появятся в директории `dist/` (уже содержит пример сборки — она будет перезаписана). Для локального просмотра собранной версии используйте любой статический сервер, например:

```bash
npx serve dist
```

### Проверка типов

```bash
npm run typecheck
```

Выполняет `tsc --noEmit` — проверяет TypeScript-типы без генерации файлов.

## Как пользоваться демо

1. Войти по кнопке на экране входа (поля уже заполнены).
2. На главной странице:
   - **«Создать проект»** — открыть пустой редактор;
   - **«Открыть проект»** — открыть редактор (в демо ведёт туда же);
   - **Импорт** — загрузить свой файл (JSON/SVG/PNG/JPG) через `ImportModal`, план подставится в редактор.
3. Внутри редактора вкладки в верхней панели переключают режимы:
   - **Редактор** — расстановка объектов и зонирование на холсте;
   - **Инвентаризация** — сводные метрики и список оборудования;
   - **Проверка** — список найденных ошибок планировки;
   - **ИИ-ассистент** — рекомендации с кнопкой применения;
   - **3D** — трёхмерный просмотр текущего плана.

Для быстрой демонстрации без собственного файла удобно использовать готовый пример из `src/data/demoPlan.ts` — он загружен по умолчанию в состоянии приложения.

## Данные и хранение

В текущей демо-версии все данные (план, объекты, зоны) хранятся **в памяти приложения** (React state), без сохранения в файл или базу данных, — при перезагрузке страницы данные сбрасываются к демо-плану. Пакет `@supabase/supabase-js` присутствует в зависимостях, но клиент нигде не инициализируется и не используется — переменные окружения для подключения к Supabase не требуются, `.env`-файл для запуска не нужен.

Для production-сценария архитектура предполагает подключение защищённого backend-API с авторизацией и постоянным хранилищем — в демо это не реализовано намеренно, чтобы упростить локальный запуск и проверку.

## Известные ограничения демо-версии

- Авторизация — заглушка (любые данные в форме входа принимаются, реальная проверка не выполняется).
- Нет сохранения данных между сессиями/перезагрузками страницы.
- ИИ-рекомендации в `AIAssistant` работают на предзаданной логике/данных внутри приложения, а не через внешний LLM API (это точка расширения, описанная в архитектуре решения).
- Для проверки достаточно `npm install` и `npm run dev` — внешние сервисы, ключи API или переменные окружения не требуются.
